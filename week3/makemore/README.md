## 一、bigram：计数与神经网络是同一个模型

计数模型：统计相邻字符对，每行归一化成概率，NLL = **2.4540**（全量 32033 行）。

神经网络：`one-hot(27) → Linear(27,27,bias=False) → cross_entropy`，无隐层无激活，训练 600 步后 nll = **2.4604**。

差 0.0064，来自 L2 正则（`0.01 * mean(W²)`）。不加正则能到 **2.4540**，与计数完全一致。

概率逐项对照：

```
'.' → a   nn 0.1373   counts 0.1377
'.' → b   nn 0.0407   counts 0.0408
'.' → e   nn 0.0476   counts 0.0478
```

**结论：softmax + 交叉熵 + 梯度下降收敛到的解，就是 log(计数矩阵)。** 这是这一周第一个要亲手验证的等式。

训练起点 nll 3.3019，对应 `log(27) = 3.296` —— 初始权重接近 0 时输出接近均匀分布。

### 不加正则会怎样

| | nll | max\|W\| | 最小 p（未见转移） |
|---|---|---|---|
| 无正则 | **2.4540** | 10.12 | 5.2e-07 |
| L2=0.01 | 2.4604 | 4.31 | 6.8e-04 |

不加正则不会 `nan` —— `cross_entropy` 走 logsumexp 路径，数值稳定。真实后果是**模型对 102 个未见转移无限自信**，泛化时会崩。

## 二、MLP：更多上下文有用

3 字符上下文 + embedding + tanh 隐层，同一个 split（7:2:1，seed=0，名字级划分，已去重）。

| 模型 | 参数 | dev NLL |
|---|---|---|
| 计数基线（train 建表 +1 平滑 → dev） | — | 2.4581 |
| MLP emb=2 hidden=100 | 3,481 | 2.0730 |
| MLP emb=10 hidden=200 | 11,897 | 2.0058 |

**上下文从 1 个字符扩到 3 个，dev NLL 降 15.7%。**

### 容量对比

| | 参数 | 最佳步 | dev | test | train@最佳 | gap(train−dev) |
|---|---|---|---|---|---|---|
| emb=2, hidden=100 | 3,481 | 2300 | 2.0730 | 2.0791 | 2.0252 | 0.048 |
| emb=10, hidden=200 | 11,897 | 300 | 2.0058 | 1.9992 | 1.8889 | 0.117 |

容量提 3.4 倍：收敛快 8 倍（300 步 vs 2300 步），test 好 3.8%，但 train/dev gap 从 0.048 扩大到 0.117。

**这是同一件事的两面** —— 不是「大模型效率更高」和「大模型会过拟合」两个独立优点和缺点，而是容量提升的收益与代价。

### 过拟合判断

小模型（3,481 参数）：dev 在 step 1400 后进入平台期，train 同期也在 2.03 附近不再下降，两条线平行。**未观察到过拟合**，处于容量受限区间。

大模型（11,897 参数）：最佳点出现在 step 300，之后 train 降到 1.85 而 dev 停在 2.03，gap 拉开到 0.19。**出现过拟合**，早停正确地在 step 2300 之前停下。

### gap 为什么是负的

```
小模型  gap dev-test  +0.0061
大模型  gap dev-test  -0.0066
```

大模型的 test 比 dev 还低。原因是 **dev 的 best 是从 43 次评估里挑出来的最小值，有选择偏差**；test 只评估一次，没有偏差。

所以两个数字里，**test 的 1.9992 其实比 dev 的 2.0058 更可信**。这是早停方法固有的偏差，不必修正，但要写清楚。

## 三、踩到的坑

### 数据泄漏（两处）

1. **按 pair 划分会泄漏** —— 一个名字产生多个上下文，同一个名字的 pair 落进 train 和 dev 两边，等于 dev 里的样本训练时见过。必须按**整个名字**划分。
2. **`names.txt` 有 2539 行重复** —— 32033 行只有 29494 个不同名字。不去重的话，同一名字的副本会被分到不同集合。`load_names()` 里已 `sorted(set(...))`。

### 学习率

- Adam + 全批量，小模型 `lr=0.01`。用 `lr=0.1` 会在 1500 / 3200 / 5100 步出现尖峰，loss 从 2.18 飙到 12.34 再慢慢爬回来，最终停在比中途更差的位置。
- 即使 `lr=0.01`，大模型在 step 2100 仍有一次 2.85 的尖峰。

**判据：loss 出现尖峰并反复恢复 = 学习率太大，不要怀疑模型结构。**

### GC 与引用环

`Value._backward` 闭包捕获了自己，形成引用环，只能靠循环 GC 回收。开着 GC 计时，同一份代码的 median 会在 8 ms 和 120 ms 之间跳。训练循环里 `gc.disable()` 之后稳定，并且快 30%。

### 无平滑的计数模型在 dev 上发散

```
baseline MLE  → dev: inf   (25 个 pair 在 train 里从未出现)
baseline +1   → dev: 2.4581
```

dev 有 25 / 42229 个 pair 概率为 0，`log(0)` 发散。加一平滑（`counts += 1` 再归一化）才能得到有限值。

**注意平滑要加在计数上、归一化之前**，加在概率上会让行和不再等于 1。

### 早停的阈值被噪声欺骗

`best_nll - 1e-4` 太宽松。dev 的评估噪声约 ±0.005，所以 2.0920 → 2.0919 这种 0.0001 的「进步」也会重置 stale 计数，导致耐心被反复重置、训练多跑几千步。

真要早停，阈值应该设到 0.005 以上，或把 patience 从 20 降到 5。

### Jupyter 的模块缓存

改了 `value.py` 之后重跑 cell 不生效 —— `from value import X` 只在第一次真正执行。必须重启内核，或 `%autoreload 2`。`.py` 脚本没有这个问题。

## 四、已知局限

1. **`flatten` 用 `view`，输入必须是连续张量。** MLP 里用了 `e.view(...)`，如果以后改成 permute 之后接 view 会报错，应改用 `reshape`。
2. **前缀超过 3 个字符时，只有最后 3 个进入上下文。** 模型结构的硬限制，不是 bug。
3. **采样质量没有量化指标。** 只有人眼看，没有自动评估。
4. **`MAXSTEPS = 100000`，实测约 0.084 秒/步。** 大模型更慢，第一次跑建议先设 20000。
5. **`mlp.py` 和 `split.py` 各有一份训练循环。** `model.py` 只抽走了结构，训练逻辑重复。改超参要改两处。
